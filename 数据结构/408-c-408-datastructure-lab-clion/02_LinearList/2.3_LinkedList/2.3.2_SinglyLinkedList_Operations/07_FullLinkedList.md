# 2.3.2 单链表的基本操作

本节已有七个拆分 cpp，保留原样；以 `07_FullLinkedList.cpp` 为综合入口并建立同名笔记，覆盖 `01_Init.cpp` 至 `06_TailInsert.cpp` 的学习内容。初始化和按位查找已有学习实现，其他操作仍待完成。以下教材操作要点不表示答案均已实现。未提供王道正文，指定版本的表述、例外待核对。

## 1. 核心概念

- 本笔记默认**带头结点、非循环单链表**，头指针为 `L`，元素位序从 1 开始，头结点可视为第 0 个结点。
- 按位插入、删除先定位前驱，再改链接；寻找前驱的时间不能从完整操作复杂度中省略。
- 修改调用者的头指针使用 `LinkList &L`；仅遍历结点通常传 `LinkList L` 即可。

## 2. 必会代码 / 操作

以下为局部操作片段，结点类型仍为 `LNode`，不用 STL。动态结点若用 `malloc` 分配则用 `free` 释放；若用 `new` 分配则用 `delete`，不能混用。

| 练习文件 | 操作和对应关系 |
|---|---|
| `01_Init.cpp` | 申请头结点，检查申请结果，令 `L->next = nullptr`；头结点数据域不必存元素 |
| `02_Search.cpp` | 按位从头沿链计数；按值从 `L->next` 开始，遇到首个匹配结点返回，失败返回空指针 |
| `03_Insert.cpp` | 插入第 i 个元素：找到第 i−1 个结点 p，再将新结点接入其后 |
| `04_Delete.cpp` | 删除第 i 个元素：找到前驱 p，保存被删结点 q、返回其数据，再断链并释放 q |
| `05_HeadInsert.cpp` | 每次插在头结点之后；结果次序与输入相反 |
| `06_TailInsert.cpp` | 尾指针 r 初始指向头结点；每次接到 r 后，再令 r 指向新结点；结果次序与输入相同 |
| `07_FullLinkedList.cpp` | 求表长从首元计数；遍历先判当前指针；销毁时先保存后继再释放当前结点 |

已知前驱 p，在其后插入 s（s 已成功分配）：

```cpp
s->next = p->next;  // 先保存原后继
p->next = s;
```

删除 p 的后继（事先保证 `p != nullptr && p->next != nullptr`）：

```cpp
LNode *q = p->next;
e = q->data;
p->next = q->next;
// 按 q 的分配方式释放 q
```

尾插每轮执行 `r->next = s; r = s;`，建表结束保证 `r->next = nullptr`；头插复用上述后插片段，令 p 为 L。

## 3. 边界条件

- 已初始化带头结点空表：`L->next == nullptr`；不得直接解引用尚未有效初始化的 L。
- 长度 n：插入合法位序为 **1 ≤ i ≤ n+1**；删除、取元素为 **1 ≤ i ≤ n**。空表可在位置 1 插入，不能删除元素。
- 按位查找若采用王道常见 `GetElem(L, 0)` 返回头结点的约定，这是辅助定位前驱，不代表第 0 个数据元素存在；负位序和超范围返回空指针。
- 首位置插删的前驱是头结点；删除尾结点后，前驱 `next` 变为空；删除唯一元素后恢复空表。
- 按值查找可能有重复值，常规 `LocateElem` 返回第一个匹配结点；失败或空表返回空指针。
- 新结点申请失败时应返回失败，不得解引用；失败前不能破坏原链。
- 尾插输入零个元素时 r 仍指向头结点，头结点后继必须为空。
- 销毁后 L 应置空；“清空”通常保留头结点，“销毁”释放头结点，二者约定要分清。

## 4. 易混概念辨析

- **位序与结点指针**：第 i 个元素不是内存中第 i 个连续位置，必须沿链定位。
- **后插与前插**：已知 p 后插可直接改链；前插通常需要寻找 p 的前驱。某些题允许“复制数据再后插”的技巧，它改变数据与结点的对应关系，不能用于要求保持结点身份的场景。
- **删除结点与释放空间**：断开链接不等于释放；释放后不得继续访问 q。
- **已知结点删除的技巧**：将后继数据复制给当前结点，再删除后继，可实现 O(1) 的等效元素删除；当前结点为尾结点时不适用，也不等同于物理删除指定结点。

## 5. 选择题细节

| 操作 | 时间复杂度 | 辅助空间 |
|---|---|---|
| 初始化、已知前驱后的插入/删除 | O(1) | O(1) |
| 按位查找第 i 个结点 | O(i)，最坏 O(n) | O(1) |
| 按值查找、求表长、遍历 | 最坏 O(n) | O(1) |
| 按位插入、按位删除 | 最坏 O(n)，主要花在定位 | O(1) |
| 头插建表、维护尾指针的尾插建表 | O(n) | O(1)，不含新建链表 |
| 清空、销毁 | O(n) | O(1) |

- 已知被删结点指针但未知其前驱，一般不能直接保证 O(1) 删除，需结合是否允许复制数据、是否为尾结点判断。
- 不维护尾指针而每次从头找到尾部，尾插建 n 个元素会达到 O(n²)。
- 头插可用于逆置，尾插可用于保持顺序；“链表插入不移动元素”不意味着完整按位插入总是 O(1)。
- 若建表用特殊输入值作为结束标记，该值不作为元素存入；结束标记取值以教材或题目约定为准。
- 插入两条赋值语句不能随意交换，否则原后继可能丢失，或新结点出现自环。

## 6. 大题 / 算法题考法

- 写出初始化、按位/按值查找、插入、删除、头插和尾插，说明定位起点与合法位序。
- 追踪指针修改后的链，检查是否断链、漏结点、成环；释放前保留后继。
- 头插用于逆序组织结果，尾插用于保持原次序。复杂度分析要计入查找，不提前展开后续综合算法。

## 7. 我的错误

来源：教学对话《代码学数据结构》的按位查找练习，并核对当前 `02_Search.cpp`。2.3.1 的遍历错误仍保留在该节笔记中。

### 1. 算法假设带头结点，测试链表却不带头结点

- **曾经的写法**：让 L 指向存放 10 的首元结点，`GetElem` 却从 `p = L, j = 0` 开始计数。
- **结果**：链为 `10 → 20 → 30` 时，`GetElem(L, 2)` 走两步返回 30，而预期第 2 个元素是 20。
- **正确思路**：算法和测试链表的表示必须一致。当前采用带头结点版本：`L → head → 10 → 20 → 30`，头结点记作位置 0，首元记作位置 1。
- **当前状态**：已补独立头结点并令 L 指向它，该错误已改正。

### 2. 给 head 赋地址，却传入未初始化的 L

- **曾经的写法**：声明 `LinkList L;`，另外写 `LNode* head = &a;`，随后调用 `GetElem(L, 2)`。
- **原因**：head 和 L 是不同的指针变量；给 head 赋值不会初始化 L。传入未初始化指针，后续访问没有有效地址保证，属于未定义行为。
- **正确思路**：先明确实际的链表入口，再将这个已初始化的指针传给函数。带头结点版本令 `head.next = &a; LinkList L = &head;`。
- **当前状态**：当前 L 已指向独立头结点，该错误已改正。

### 3. 查找返回后直接访问 `p->data`，没有判空

- **实际写法**：`LNode* p = GetElem(L, 2); cout << p->data;`。
- **原因**：当前合法位序能返回结点，但超范围查找会返回 `nullptr`，直接解引用会产生未定义行为；一次正确输出不能证明边界已处理。
- **正确思路**：先检查返回值，再读取数据。

```cpp
if (p != nullptr) {
    cout << p->data;
}
```

- **当前状态**：当前 cpp 仍直接输出 `p->data`，判空待补；这里只记录，不修改答案。

补充辨析：`GetElem` 返回结点地址，p 是指针，`p->data` 才是元素值；返回 `nullptr` 表示未找到。关于返回类型的提问属于学习疑问，不单独算作已犯错误。

## 8. 一句话复习

单链表按位操作先找前驱，再保住原链接改指针；头插逆序、尾插保序，定位成本不能漏算。
