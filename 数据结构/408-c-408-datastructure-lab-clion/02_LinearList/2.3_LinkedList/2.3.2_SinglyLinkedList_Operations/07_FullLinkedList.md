## 1. 核心概念

- 本笔记默认**带头结点、非循环单链表**，头指针为 `L`，元素位序从 1 开始，头结点可视为第 0 个结点。
- 按位插入、删除先定位前驱，再改链接；寻找前驱的时间不能从完整操作复杂度中省略。
- 修改调用者的头指针使用 `LinkList &L`；仅遍历结点通常传 `LinkList L` 即可。
- 四个定位起点：按位查找从 `L, j = 0` 开始；按值查找、求表长、遍历从 `L->next` 开始；插入和删除第 i 个元素先找第 i−1 个结点。
- 按位插入：新元素最终占据位置 i，原第 i 个及其后元素位序后移；按位删除：删除原位置 i 的元素，后续元素位序前移。结点本身不需要整体搬移。

## 2. 必会代码 / 操作

练习时可用公共辅助函数快速建表，不必重复手写三个结点：

```cpp
int values[] = {10, 20, 30};
LinkList L = CreateList(values, 3); // 保持数组顺序，自动带头结点
// 在这里调用本次练习的操作
PrintList(L);
DestroyList(L); // 释放全部动态结点，L 变为 nullptr
```

`CreateList(nullptr, 0)` 创建带头结点的空表；负长度或非零长度配空数组指针会抛出异常。传入长度不能超过数组实际元素数。`DestroyList` 只用于全部结点由 `new` 分配的链表，不用于原来的局部 `head、a、b、c`。这两个函数作为练习辅助提供，不代表已完成尾插和销毁算法的学习。

新练习在同目录中写 `#include "LinkedList.h"`，即可使用 `LNode`、`LinkList`、`InitList`、`GetElem`、`LocateElem` 和 `PrintList`。本次正在练习的新函数仍写在 cpp 中，后续需要复用时再纳入头文件。不要再复制同名类型和函数定义，否则会重定义。公共函数默认带头结点的非循环单链表，不能直接用于无头结点或循环链表。

以下为局部操作片段，结点类型仍为 `LNode`，不用 STL。动态结点若用 `malloc` 分配则用 `free` 释放；若用 `new` 分配则用 `delete`，不能混用。

### 初始化、查找和表长

初始化只申请头结点并置空后继，不会自动填入数据。公共 `InitList` 使用普通 `new`，分配失败抛异常；不能把 `return true` 理解成已处理分配失败。`CreateList` 是用于准备数据的辅助函数，与亲自完成建表练习区分。

`GetElem(L, i)` 返回结点地址；读取数值用 `p->data`，后续操作可使用 `p->next`。`LocateElem(L, x)` 跳过头结点，遇到第一个 `data == x` 的结点即停止。

求表长的修改建议（当前综合代码误写为 bool）：

```cpp
int LengthList(LinkList L) {
    int length = 0;
    for (LNode* p = L->next; p != nullptr; p = p->next)
        length++;
    return length;
}
```

这里假定 L 是有效头指针；空表返回 0，头结点不计数。判空为 `L->next == nullptr`，遍历和求表长都不需要改变调用者的 L。

### 插入和删除

已知前驱 p，在其后插入 s（s 已成功分配）：

```cpp
s->next = p->next;  // 先保存原后继
p->next = s;
```

删除 p 的后继（事先保证 `p != nullptr && p->next != nullptr`）：

```cpp
LNode *q = p->next;
e = q->data;
p->next = q->next;
delete q; // 当前练习使用 new 分配
```

尾插每轮执行 `r->next = s; r = s;`，建表结束保证 `r->next = nullptr`；头插复用上述后插片段，令 p 为 L。

当前 `ListInsert` 可以复用 `GetElem(L, i - 1)` 与 `Insert(p, x)`。当前 `Insert` 不改 p 本身，只改 p 指向结点的链接，所以引用参数并非此操作的必要条件。

按位删除的关键检查是：

```cpp
if (i < 1) return false;
LNode* p = GetElem(L, i - 1);
if (p == nullptr || p->next == nullptr) return false;
```

找到前驱不等于存在可删除元素；例如位置 n+1 的前驱是尾结点，但尾结点没有后继。e 是输出参数，删除失败时不能当作本次有效结果使用。

### 头插、尾插和销毁

头插每次修改 `L->next`，尾插每次修改尾结点的 `next` 并更新 r。仅用于手工理解顺序的示意：输入 `10 20 30`，头插得到 `30 → 20 → 10`，尾插得到 `10 → 20 → 30`；这不是新增运行结果。

两种建表方式输入停止规则目前不同：头插中的 `-1` 是正常元素；尾插中的 `-1` 是结束标记。需要统一时应先明确题目约定。所有建表结点由 `new` 分配，结束使用后可调用公共 `DestroyList`；不要释放原先在栈上声明的局部结点。

销毁的可靠循环条件是剩余链表入口 `L != nullptr`：

```cpp
while (L != nullptr) {
    LNode* p = L;
    L = L->next; // 先保留后继
    delete p;   // 再释放当前结点，含头结点
}
```

结束时 L 为 nullptr，不能再通过它判 `L->next`。上述片段假定所有结点均由 new 分配且链表非循环。

## 3. 边界条件

- 已初始化带头结点空表：`L->next == nullptr`；不得直接解引用尚未有效初始化的 L。
- 长度 n：插入合法位序为 **1 ≤ i ≤ n+1**；删除、取元素为 **1 ≤ i ≤ n**。空表可在位置 1 插入，不能删除元素。
- 按位查找若采用王道常见 `GetElem(L, 0)` 返回头结点的约定，这是辅助定位前驱，不代表第 0 个数据元素存在；负位序和超范围返回空指针。
- 首位置插删的前驱是头结点；删除尾结点后，前驱 `next` 变为空；删除唯一元素后恢复空表。
- 按值查找可能有重复值，常规 `LocateElem` 返回第一个匹配结点；失败或空表返回空指针。
- 新结点申请失败时应返回失败，不得解引用；失败前不能破坏原链。
- 尾插输入零个元素时 r 仍指向头结点，头结点后继必须为空。
- 销毁后 L 应置空；“清空”通常保留头结点，“销毁”释放头结点，二者约定要分清。
- `p == nullptr || p->next == nullptr` 依靠短路求值避免解引用空指针，不能交换两项检查顺序。
- `new` 分配失败会抛异常；若使用 `new (nothrow)` 才可用空指针判断失败。当前拆分建表未处理途中分配失败的部分链回收，公共 `CreateList` 已处理。
- 头插和尾插在零次成功输入时均只有头结点；尾插 r 必须初始指向 L，不能是未初始化指针。
- 头插或尾插遇到输入失败会结束循环；当前函数不区分正常 EOF 与输入格式错误。尾插把 -1 用作标记时，不能把 -1 同时作为待存数据。

## 4. 易混概念辨析

- **位序与结点指针**：第 i 个元素不是内存中第 i 个连续位置，必须沿链定位。
- **后插与前插**：已知 p 后插可直接改链；前插通常需要寻找 p 的前驱。某些题允许“复制数据再后插”的技巧，它改变数据与结点的对应关系，不能用于要求保持结点身份的场景。
- **删除结点与释放空间**：断开链接不等于释放；释放后不得继续访问 q。
- **传指针与传指针引用**：传 `LinkList L` 也能改变结点的 data、next；传 `LinkList& L` 则还能改变调用者保存的入口地址。是否修改入口决定是否需要引用，并非所有链表函数都必须使用引用。
- **长度与真假**：表长应返回 int；bool 只区分 0 和非 0，长度 1、2、3 都会变为 true。
- **已知结点删除的技巧**：将后继数据复制给当前结点，再删除后继，可实现 O(1) 的等效元素删除；当前结点为尾结点时不适用，也不等同于物理删除指定结点。

## 5. 选择题细节

| 操作 | 时间复杂度 | 辅助空间 |
|---|---|---|
| 初始化、已知前驱后的插入/删除 | O(1) | O(1) |
| 按位查找第 i 个结点 | O(i)，最坏 O(n) | O(1) |
| 按值查找、求表长、遍历 | 最坏 O(n) | O(1) |
| 按位插入、按位删除 | 最坏 O(n)，主要花在定位 | O(1) |
| 头插建表、维护尾指针的尾插建表 | O(n) | O(1)，不含新建链表 |
| 清空、销毁 | O(n) | O(1) |

- 已知被删结点指针但未知其前驱，一般不能直接保证 O(1) 删除，需结合是否允许复制数据、是否为尾结点判断。
- 不维护尾指针而每次从头找到尾部，尾插建 n 个元素会达到 O(n²)。
- 头插可用于逆置，尾插可用于保持顺序；“链表插入不移动元素”不意味着完整按位插入总是 O(1)。
- 若建表用特殊输入值作为结束标记，该值不作为元素存入；结束标记取值以教材或题目约定为准。
- 插入两条赋值语句不能随意交换，否则原后继可能丢失，或新结点出现自环。

## 6. 大题 / 算法题考法

- 写出初始化、按位/按值查找、插入、删除、头插和尾插，说明定位起点与合法位序。
- 追踪指针修改后的链，检查是否断链、漏结点、成环；释放前保留后继。
- 头插用于逆序组织结果，尾插用于保持原次序。复杂度分析要计入查找，不提前展开后续综合算法。

## 7. 我的错误

来源：教学对话《代码学数据结构》的按位查找练习，并核对当前 `02_Search.cpp`。2.3.1 的遍历错误仍保留在该节笔记中。

### 1. 算法假设带头结点，测试链表却不带头结点

- **曾经的写法**：让 L 指向存放 10 的首元结点，`GetElem` 却从 `p = L, j = 0` 开始计数。
- **结果**：链为 `10 → 20 → 30` 时，`GetElem(L, 2)` 走两步返回 30，而预期第 2 个元素是 20。
- **正确思路**：算法和测试链表的表示必须一致。当前采用带头结点版本：`L → head → 10 → 20 → 30`，头结点记作位置 0，首元记作位置 1。
- **当前状态**：已补独立头结点并令 L 指向它，该错误已改正。

### 2. 给 head 赋地址，却传入未初始化的 L

- **曾经的写法**：声明 `LinkList L;`，另外写 `LNode* head = &a;`，随后调用 `GetElem(L, 2)`。
- **原因**：head 和 L 是不同的指针变量；给 head 赋值不会初始化 L。传入未初始化指针，后续访问没有有效地址保证，属于未定义行为。
- **正确思路**：先明确实际的链表入口，再将这个已初始化的指针传给函数。带头结点版本令 `head.next = &a; LinkList L = &head;`。
- **当前状态**：当前 L 已指向独立头结点，该错误已改正。

### 3. 查找返回后直接访问 `p->data`，没有判空

- **实际写法**：`LNode* p = GetElem(L, 2); cout << p->data;`。
- **原因**：当前合法位序能返回结点，但超范围查找会返回 `nullptr`，直接解引用会产生未定义行为；一次正确输出不能证明边界已处理。
- **正确思路**：先检查返回值，再读取数据。

```cpp
if (p != nullptr) {
    cout << p->data;
}
```

- **当前状态**：当前 cpp 已在输出 `p->data` 前检查 `p != nullptr`，该错误已改正。

补充辨析：`GetElem` 返回结点地址，p 是指针，`p->data` 才是元素值；返回 `nullptr` 表示未找到。关于返回类型的提问属于学习疑问，不单独算作已犯错误。

### 5. 综合文件使用未定义的 LinkedList，并重复写公共函数

- 来源：当前 `07_FullLinkedList.cpp` 与 `LinkedList.h`。

### 8. 销毁前判断了未初始化指针

- 来源：当前综合文件 `DestroyList`，先声明 `LNode* p;`，随后 `while (p != nullptr)`。

- 修改建议：循环判断 `L != nullptr`，每轮先保存当前结点和后继，再 delete。公共头文件的销毁函数已按这一思路实现。

- 初始化或建表后直接 return；删除一个结点不代表剩余链表和头结点已经释放。
- 修改建议：最后调用公共 `DestroyList(L)`；当前这四个练习尚未添加。此项与错误的综合销毁循环分别处理。

## 8. 一句话复习

单链表按位操作先找前驱，再保住原链接改指针；头插逆序、尾插保序，定位成本不能漏算。
