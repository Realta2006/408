# 2.3.3 双链表

对应代码：`2.3.3_DoublyLinkedList.cpp`，目前为 TODO。以下记录本节必要操作，不表示用户已实现。默认带头结点的**非循环双链表**；未提供王道正文，指定版本的表述、例外待核对。循环双链表留到 2.3.4。

## 1. 核心概念

- 双链表结点有数据域、前驱指针 `prior`、后继指针 `next`，可以沿两个方向访问。
- 双向链接不改变线性表的逻辑结构，也不使其获得随机存取能力。
- 相邻结点 p、q 满足 `p->next == q`、`q->prior == p`；涉及空指针时不能直接解引用该关系。

## 2. 必会代码 / 操作

```cpp
struct DNode {
    int data;
    DNode *prior, *next;
};
```

当前 cpp 的三个 TODO 分别对应结点定义、插入时恢复双向链接、删除时重新连接前后结点。以下片段均假定结点指针有效，s 为新结点。

**在 p 后插入 s**（p 可以是头结点，也可以是尾结点）：

```cpp
s->next = p->next;
if (p->next != nullptr)
    p->next->prior = s;
s->prior = p;
p->next = s;
```

**在数据结点 p 前插入 s**（带头结点，故 p 有前驱）：

```cpp
s->prior = p->prior;
s->next = p;
p->prior->next = s;
p->prior = s;
```

**删除数据结点 q**（q 有有效前驱，不允许删除头结点）：

```cpp
q->prior->next = q->next;
if (q->next != nullptr)
    q->next->prior = q->prior;
// 按 q 的分配方式释放 q
```

若使用 `malloc/free` 或 `new/delete`，必须成对使用。上述片段不包含查找、分配失败处理和返回值，完整函数须补齐这些条件。

## 3. 边界条件

- 本笔记约定头结点 `prior == nullptr`；初始化成功的空表为 `L->next == nullptr`，头结点不计表长。
- 在尾结点后插入：原 `p->next == nullptr`，不能执行 `p->next->prior = s`，因此需要判断。
- 删除尾结点：q 没有后继，只需让前驱的 `next` 为空，再释放 q。
- 删除唯一数据结点：头结点 `next` 恢复为空；头结点仍保留。
- 带头结点首元结点的 `prior` 指向头结点，不为空；无头结点时首元的前驱为空，首位置插删须另外处理并更新头指针。
- 不允许把头结点作为普通数据结点删除；空表没有可删除元素。
- 若另维护尾指针，插入新尾结点或删除旧尾结点时还须更新尾指针。

## 4. 易混概念辨析

- **双链表 ≠ 循环链表**：双向描述前驱/后继两个方向，循环描述是否首尾相接。
- **头指针 ≠ 头结点**：L 是指针，L 指向的附加结点才是头结点。
- **双向一致性**：只改 `next` 可能正向看似正常，但反向链已错误；插删要检查两个方向。
- **顺序限制**：不是必须死记唯一赋值顺序，而是在覆盖旧链接前，必须保存或使用完它。上述前插若过早令 `p->prior = s`，就丢失了通过 p 访问原前驱的路径。

## 5. 选择题细节

- 已知有效结点指针：前插、后插、删除该数据结点均可 O(1)，无需像普通单链表那样遍历找前驱。
- 从头按位或按值定位仍最坏 O(n)；含定位的插入、删除仍最坏 O(n)。
- 遍历 n 个元素 O(n)，辅助空间 O(1)；存储空间 O(n)，每个结点比单链表多一个前驱指针域。
- 一般中间插入要建立新结点两条链接并修改两侧结点各一条链接；一般中间删除要修改两侧各一条链接。端点遇到空后继时，修改次数会不同，不能脱离条件死背次数。
- 双链表只能沿链接顺序定位，两个指针域不等于能按下标直接访问。
- 无头结点、带头结点、是否维护尾指针会影响边界代码；题目给定结构必须先看清。

## 6. 大题 / 算法题考法

- 根据 `前驱 ⇄ 当前 ⇄ 后继` 写插删代码，分别验证正向和反向链接。
- 补全缺失的指针赋值，判断错误顺序导致的断链、自环或反向链接错误。
- 分析已知结点与需要查找结点两种复杂度；检查首元、尾结点、唯一元素三类情况。
